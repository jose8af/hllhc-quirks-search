# Advisor ruling: `dev.pu1` and the interaction-level seed reuse (Ketil, Fable; 2026-11-24)
1. **Q1: no violation of the frozen text.** STR defines independence in the inventory by the job-seed streams only: "Seed streams are disjoint by construction: the job seed is blake2b("qv2|stream|chunk") ... and every stream name is unique" (STR l.2086-2088); the column "must be independent of" (l.2092; row 12 l.2105, row 14 l.2108, row 16 l.2110) has no other operational definition. `seed_disjoint.json` shows 0 shared job seeds for all 15 pairs, also over chunks 0..99,999. The frozen rule is met.
2. **But the rule does not deliver strict statistical independence, and that must be said, not hidden.** The per-interaction seeds are drawn in [1, 9×10⁸) (`acts/stage4/code/s4pu.py` l.142, re-seed l.63). My own count agrees with Hilde's ESTIMATE: 1 − exp(−4.8×10⁶/9×10⁸) = 0.53 % of dev.pu1 interactions, about 1 per event (P3E §6, l.116-123).
3. **It is immaterial for the roles.** A reused seed gives the same minimum-bias interaction at another vertex (σ_z of the luminous region) among ≈ 199 other interactions, so not the same hits on the same modules. Even if every candidate came from one interaction, at most ≈ 0.5 % of counts would be correlated between the samples, against a cap s_model ≤ 0.135 and a statistical error of ±0.034 at R06 (Freja point A5, l.18). dev.pu1 remains a valid fresh held-out sample for the one redesign (Freja point 5, l.6; A2, l.15).
4. **Q2: yes, launch `p3-e-devpu1` as defined, now** (Freja A4, l.17: a frozen MUST line; not producing it would be a deviation). Pre-flight, budget check and the seal of A2 as ruled. No chain edit before the launch.
5. **Not noticed in P3E, to be stated with it:** the same scheme reuses seeds *inside* one sample. For prod.pu1 (4.8×10⁶ interactions) about 0.53 % of interactions share a seed with another interaction of prod.pu1 (≈ 1.3×10⁴ pairs, ESTIMATE). Same argument, same size; it is a v1 property also present in c1.pu1.
6. **Q3 (a): a statement goes into PREREG_v2; the orchestrator may and must add it.** PREREG lists "the sizes and seed streams (§4.17)" (STR l.2346). A disclosure does not change a criterion, a tolerance or a sample. Text: job seeds disjoint (measured, 0); interaction seeds from a 9×10⁸ space, hence the overlap fractions dev/prod, c1/prod, reserve/prod and within prod; the bound of point 3.
7. **Replace the ESTIMATE by exact numbers before the freeze.** The interaction seeds follow from the event seed alone by numpy (`s4pu.py` l.137-142), with no Pythia run. One small script (not a chain edit, minutes of CPU) lists them for dev.pu1, c1.pu1, prod.pu1 and reserve.pu1 and counts the overlaps between and within samples. Check first how the event seed is derived from the job seed. This can be done although prod.pu1 does not exist.
8. **Q3 (b): no fix of the seed range is decided now, and it is not the orchestrator's to decide.** (i) A wider range is impossible: Pythia's `Random:seed` has max 900,000,000 (`acts/.pixi/envs/default/share/Pythia8/xmldoc/RandomNumberSeed.xml` l.17), and `s4pu.py` l.63 takes the seed modulo that. A real fix means a new scheme (sub-ranges per stream, or draws without replacement): an edit of the v1 chain in `acts/`, so the test sample would be generated by another code version than the samples the estimators were developed on, and C1's "v1 code with logged port edits" (COMMITMENTS l.168) would no longer describe it. (ii) That is a method change to a production sample: it belongs to the 4-bot freeze review (STR l.2337), which must see it before any production sample exists.
9. **What the orchestrator does:** puts one explicit item on the freeze-review agenda: "interaction-seed scheme for prod.pu1 / prod.pu2 / reserve.pu1: keep v1 (disclosed, with the exact overlaps of point 7) or partition the 9×10⁸ space per stream". My recommendation to that review: **keep v1**, because the effect is ≈ 0.5 % and a chain edit costs a provenance entry, a regression and a version difference between development and test.
10. **Must not:** edit `s4pu.py` now; describe dev.pu1 and prod.pu1 as "statistically independent" without the qualifier; quote 0.5 % as measured before point 7 is done.
11. **Not checked by me:** that the campaign JSON reproduces the hashed job-seed formula (I read Hilde's JSON, not the code path of the job script); the derivation of the event seed from the job seed; the claim of point 3 by a measurement (it is an argument with a bound, not a test).
